# 水下考古潜水记录

## 使用说明

直接打开 `index.html` 使用。点击沉船平面图添加标记，管理潜次档案，支持筛选、编辑、删除、时间线查看、导出和导入JSON。

### 多遗址项目管理

系统支持在同一个浏览器中管理多个沉船或遗址项目，每个项目拥有独立的数据集。

#### 快速切换项目

- 顶部工具栏左侧显示**项目选择器**（下拉菜单），直接选择即可切换到其他项目
- 切换项目时，地图标记、侧栏列表、潜次档案、测距记录、比例尺配置、导入错误记录等**全部同步刷新**，不会串用上一个项目的数据

#### 项目管理面板

点击顶部「**管理项目**」按钮打开项目管理面板，可执行以下操作：

- **创建新项目**：在顶部输入框输入遗址名称，点击「创建项目」按钮，新项目自动成为当前项目，**新项目为空白项目，不含任何默认标记或潜次**
- **切换项目**：点击任意非当前项目卡片上的「切换」按钮
- **重命名项目**：点击「重命名」按钮，在弹出框中输入新名称
- **归档项目**：点击「归档」按钮将项目放入归档区（项目选择器中不显示，数据保留）。**注意：系统至少保留一个活动项目，无法归档最后一个活动项目**
- **恢复项目**：已归档项目显示「恢复」按钮，点击后重新出现在项目选择器中
- **删除项目**：点击「删除」按钮永久删除项目及其所有数据（不可恢复）
- **项目卡片信息**：每张卡片显示项目名称、标记数量、潜次数量、存储空间占用；当前项目有绿色「当前项目」标签，已归档项目有灰色「已归档」标签

#### 数据隔离说明

每个项目拥有独立的存储分区，包含：
- 标记数据（含影像附件、审核信息）
- 潜次档案
- 测距与网格记录
- 比例尺校准信息
- 导入错误记录
- 导出文件名（自动使用项目名）

首次升级时，系统会自动将原有数据迁移到「默认遗址」项目中。

#### 模块切换

右侧面板分为四个标签页：

- **标记管理**：管理水下考古标记的添加、编辑、删除，包括审核信息
- **审核看板**：按四种审核状态管理标记，支持拖拽和按钮切换状态
- **潜次档案**：管理每次下潜的档案信息，查看统计摘要
- **测距与网格**：测量距离、比例尺校准、网格显示

### 基本操作

#### 标记管理

- **添加标记**：点击地图任意位置，填写右侧表单信息后点击「保存标记」
- **编辑标记**：点击地图上的标记点或右侧列表中的标记项，修改信息后保存
- **删除标记**：选中标记后点击「删除」按钮
- **筛选标记**：使用地图上方下拉菜单按类型或潜次筛选，或切换「标记列表」/「潜次时间线」视图
- **关联潜次**：添加或编辑标记时，从下拉菜单选择所属潜次

#### 遗物分布热力图

- **开启/关闭热力图**：点击地图工具栏中的「热力图」按钮，可切换热力图覆盖层的显示状态。按钮变为黄色且显示「关闭热力图」表示已开启
- **按类型筛选热点**：在热力图控制面板的「分组」下拉中选择「陶片」「木构件」「金属件」或「未知物」，仅显示该类型遗物的分布密度
- **按潜次筛选热点**：在「分组」下拉中选择具体潜次编号（如 DIVE-01），查看单次潜水作业的标记分布
- **按审核状态筛选热点**：在「分组」下拉中选择「采集」「待复核」「已确认」或「需返潜」，按审核状态查看分布热点
- **按保存状况筛选热点**：在「分组」下拉的「按保存状况」组中选择具体描述（如「边缘残缺」「稳定」等），按遗物的实际保存状态查看分布热点；标记保存状态字段为空的可选择「未填写」项
- **调整透明度**：拖动「透明度」滑块（0%-100%），实时调整热力覆盖层的不透明度，默认 55%
- **查看图例**：控制面板底部的色阶图例显示密度从低（蓝）到高（红）的颜色映射
- **空数据提示**：当筛选条件下无符合的标记时，地图中央会显示「当前筛选条件下无标记数据」提示
- **交互兼容**：热力层不会影响原有操作，可正常点击地图新增标记、选择已有标记、使用筛选列表

#### 现场报告生成

- **打开报告弹窗**：点击右上角「现场报告」按钮
- **选择报告范围**：在下拉菜单中选择「全部数据」「按潜次筛选」「按类型筛选」或「按审核状态筛选」
- **生成报告**：点击「生成报告」按钮，弹窗内显示报告预览
- **报告内容**：统计概览卡片、类型统计表、审核状态统计表、沉船平面图SVG概览（含标记分布）、重点标记列表（待复核/需返潜）、潜次时间线（标记详情表）、导入错误摘要、比例尺信息
- **打印报告**：点击「打印报告」按钮，在新窗口打开报告HTML并自动调用浏览器打印预览，可直接打印或保存为PDF

#### 潜次档案

- **添加潜次**：在「潜次档案」标签页填写表单，点击「保存潜次」
- **编辑潜次**：点击潜次列表中的「编辑」按钮，修改后保存
- **删除潜次**：点击「删除」按钮。若该潜次有关联标记，系统会提示并自动清空关联标记的潜次字段
- **查看详情**：点击潜次列表中的「详情」按钮或直接点击列表项，查看潜次完整信息和关联标记
- **统计摘要**：潜次档案顶部显示统计数据，包括潜次总数、标记总数、平均每潜次标记数、类型数

### 标记与潜次的关联

- 所有标记通过 `dive` 字段与潜次档案自动关联
- 首次使用时，系统会根据现有标记的 `dive` 字段自动创建对应的潜次档案
- 修改潜次编号时，所有关联标记的 `dive` 字段会自动同步更新
- 删除潜次时，关联标记的 `dive` 字段会被清空，但标记本身不会被删除

### 离线多设备合并

系统支持多个潜水小组在不同设备上离线记录后，回到岸上合并数据。每台设备导出的文件包含设备编号、导出时间、标记变更日志和当前数据快照，确保合并时能完整追踪所有变更。

#### 离线导出

点击右上角「**离线导出**」按钮，导出包含完整变更日志的离线合并格式文件（文件名带 `-offline` 后缀）。

离线导出文件包含：
- **设备编号**：每台设备自动生成唯一标识，用于追踪变更来源
- **导出时间**：文件导出的精确时间戳
- **数据快照**：当前所有标记、潜次、测距、比例尺、网格配置的完整状态
- **变更日志**：记录所有增删改操作，包含操作类型、前后数据、设备ID、时间戳

#### 离线合并导入

点击右上角「**导入JSON**」按钮，选择离线导出的文件（`format` 为 `offline-merge`），系统将自动进入合并预览模式。

#### 合并结果分类

导入时系统会智能分析并分类展示以下结果：

1. **新增项**（绿色）：本地不存在的标记/潜次/测距，将直接添加
2. **修改项**（蓝色）：同ID且同编号，但内容有变化的项
3. **删除项**（红色）：导入文件中已删除，但本地仍存在的项
4. **分叉编辑**（橙色）：同编号但不同ID，表示多设备独立编辑了同一编号的标记
5. **位置疑似重复**（紫色）：不同编号但位置接近（默认阈值3%）的标记，可能是重复记录
6. **未变更项**（灰色）：完全相同的项，默认不显示

#### 冲突处理方式

对于每个分类的项，可选择不同的处理方式：

- **新增项**：添加 / 跳过
- **修改项**：保留本地 / 覆盖本地
- **删除项**：确认删除 / 保留
- **分叉编辑**：保留本地 / 覆盖本地 / 另存为新编号 / 两者都保留
- **位置疑似重复**：跳过 / 合并为一项 / 都保留

支持**批量操作**：可按分类一键设置所有项的处理方式。

#### 状态回滚

合并完成后，页面顶部会显示「**撤销合并**」提示条，点击可一键回滚到合并前的状态。快照会在下次合并前更新，或在页面刷新后失效。

#### 旧格式兼容

系统完全兼容现有旧JSON导入格式（v1.0~v6.0），导入旧格式文件时仍使用原有的导入预览流程，不会破坏已有本地数据。

### 导出JSON

点击右上角「导出JSON」按钮，当前项目的潜次档案、标记、测距、比例尺和网格配置将以完整JSON格式下载，文件名会自动使用当前项目名称（特殊字符会替换为下划线）。

导出文件包含完整数据结构：

```json
{
  "version": "2.0",
  "exportDate": "2025-06-20T08:00:00.000Z",
  "dives": [...],
  "marks": [...]
}
```

### 导入JSON

点击右上角「导入JSON」按钮，选择导出的文件进行合并导入。

系统支持两种格式：

1. **完整数据格式（v2.0）**：包含 `dives` 和 `marks` 字段的对象格式（推荐）
2. **传统标记数组格式**：仅包含标记数组（兼容旧版本导出文件）

#### 导入预览

导入前会显示预览摘要，包括潜次档案和标记数据的：

1. **新增项**（绿色）：本地不存在的新项目，将被直接添加
2. **冲突项**（黄色）：与本地编号相同的项，可选择处理方式
3. **格式错误**（红色）：数据格式有误的项，将被跳过

#### 冲突处理

对于同编号冲突的项，可针对每一项单独选择处理方式，或使用批量操作：

- **保留本地**：保留当前本地数据，忽略导入数据
- **覆盖本地**：用导入数据覆盖本地数据
- **另存为新编号**：将导入数据以新编号保存

### 数据格式

#### 潜次档案格式

```json
{
  "id": "uuid",
  "code": "DIVE-01",
  "date": "2025-06-15",
  "leader": "张教授",
  "weather": "sunny",
  "current": "weak",
  "visibility": "5-8米",
  "objective": "勘查船艉区域，采集陶瓷标本"
}
```

潜次必填字段：`code`、`date`、`leader`、`visibility`、`objective`

潜次可选字段：`weather`、`current`

天气有效值：`sunny`（晴）、`cloudy`（多云）、`rainy`（雨）、`windy`（大风）、`foggy`（雾）

水流有效值：`calm`（无流）、`weak`（弱流）、`moderate`（中流）、`strong`（强流）

#### 标记格式

```json
{
  "code": "A-017",
  "type": "ceramic",
  "dive": "DIVE-01",
  "depth": "17.8m",
  "x": 42,
  "y": 46,
  "orientation": "东",
  "condition": "边缘残缺",
  "note": "靠近船肋"
}
```

标记必填字段：`code`、`type`、`dive`、`depth`

标记可选字段：`orientation`、`condition`、`note`、`x`、`y`（坐标范围 0-100）

类型有效值：`ceramic`（陶片）、`wood`（木构件）、`metal`（金属件）、`unknown`（未知物）

### 本地持久化

所有数据自动保存在浏览器的 localStorage 中，刷新页面不会丢失。项目列表使用 `zfl30_projects`，当前项目使用 `zfl30_currentProject`，每个项目的数据使用 `zfl30_proj_<项目ID>_<数据类型>` 的独立命名空间保存。

- 项目内数据类型包括：`marks`、`dives`、`measurements`、`scale`、`grid`、`importErrors`
- 旧版本的全局数据键会在首次升级时迁移到「默认遗址」项目中

## 模块说明

### dataIO.js - 数据读写模块

负责所有数据的持久化和文件操作：
- `loadMarks()` / `saveMarks()` - 标记数据的本地存储读写
- `loadDives()` / `saveDives()` - 潜次档案的本地存储读写
- `exportFullData()` - 导出完整数据（包含潜次和标记）
- `exportMarksOnly()` - 仅导出标记数据（兼容旧版）
- `triggerFileInput()` / `readFileAsText()` / `parseJSON()` - 文件导入相关
- `isFullDataFormat()` - 检测导入文件格式

### validation.js - 数据校验模块

负责数据校验和冲突处理：
- `validateMark()` / `validateDive()` - 单项数据校验
- `validateMarkArray()` / `validateDiveArray()` - 数组校验
- `compareMarks()` / `compareDives()` - 比较本地与导入数据，识别冲突
- `resolveMarkConflicts()` / `resolveDiveConflicts()` - 解决冲突
- `addNewMarks()` / `addNewDives()` - 添加新数据
- `generateNewCode()` - 生成唯一编号

### heatmap.js - 热力图计算与渲染模块

负责遗物分布热力图的计算和渲染：
- `init()` - 初始化 Canvas 和事件监听
- `render(marks)` - 根据标记数据渲染热力覆盖层
- `toggle()` - 切换热力图显示状态
- `setState()` / `getState()` - 状态管理（开关、筛选模式、透明度、半径）
- `filterMarks(marks, filterMode)` - 按类型/潜次/保存状态筛选标记
- `calculateDensity(marks, width, height, radius)` - 基于高斯核函数计算标记密度网格
- `getColor(value, maxVal)` - 根据密度值计算对应的渐变色（蓝→青→绿→黄→橙→红）
- `getGradientCSS()` - 获取图例的 CSS 渐变色
- `resize()` - 自适应调整 Canvas 尺寸

### ui.js - 界面渲染模块

负责所有界面元素的渲染和用户交互：
- `render()` - 渲染地图标记和标记列表
- `renderDives()` - 渲染潜次列表和统计摘要
- `showDiveDetail()` - 显示潜次详情面板
- `showImportPreview()` - 显示导入预览对话框
- `showToast()` - 显示提示消息
- `switchTab()` - 切换标签页

### app.js - 主应用逻辑

负责应用初始化和业务流程控制：
- `init()` - 应用初始化，加载数据，自动创建潜次档案
- `handleSaveMark()` / `handleDeleteMark()` - 标记的增删改
- `handleSaveDive()` / `handleDeleteDive()` - 潜次的增删改
- `handleExport()` / `handleImport()` - 数据的导入导出
- `autoCreateDivesFromMarks()` - 根据已有标记自动创建潜次档案
- `applyImport()` - 应用导入结果

- 新增「遗物分布热力图」模块
- 在沉船平面图上根据标记密度生成可切换的热力覆盖层
- 支持按类型、潜次和保存状态查看分布热点
- 热力层包含图例（蓝→青→绿→黄→橙→红密度色阶）、透明度滑块控制和空数据提示
- 热力层不影响原有点击新增标记、选择标记和筛选列表的交互
- 独立的热力计算与渲染逻辑（heatmap.js）

### v5.0
- 新增「标记审核看板」模块
- 四种审核状态管理：采集、待复核、已确认、需返潜
- 看板按状态分组展示，支持拖拽和按钮两种方式切换状态
- 状态变更时记录复核意见、审核人、变更历史
- 地图标记按审核状态高亮显示不同颜色和动画
- 导入冲突预览中显示审核状态差异对比
- 导出JSON版本升级至5.0，包含完整审核信息
- 老版本数据自动兼容：加载旧标记时自动补全审核字段
